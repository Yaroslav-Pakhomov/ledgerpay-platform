# Политика безопасности

LedgerPay — portfolio-проект, а не production-платёжная или банковская система.

## Сообщения об уязвимостях

Не отправляйте реальные отчёты об уязвимостях через публичные issues.

Для боевого развёртывания настройте приватный security contact (email или форму).

## Что проект демонстрирует в части security

* **API-аутентификация через Sanctum** — защита API с помощью токенов Laravel Sanctum;
* **Policies владения счётом** — проверка, что пользователь может работать только со своими счетами и связанными ресурсами;
* **авторизация backoffice** — разграничение доступа к административным операциям;
* **ошибки в формате Problem Details** — единый структурированный формат ответов API при ошибках;
* **Correlation ID запросов** — идентификатор для трассировки одного запроса через логи и компоненты системы;
* **Rate limiting** — ограничение частоты запросов для защиты API от злоупотреблений и чрезмерной нагрузки;
* **Security headers** — HTTP-заголовки, снижающие риски типовых атак на веб-приложение;
* **неизменяемый ledger** — запрет изменения или удаления уже созданных финансовых записей;
* **неизменяемый audit log** — сохранение истории действий без возможности переписывания существующих записей;
* **ограничения PostgreSQL (constraints, triggers)** — обеспечение критичных правил целостности непосредственно на уровне базы данных;
* **проверки сверки балансов (balance reconciliation)** — контроль соответствия балансов счетов данным финансового реестра.


## Не цели проекта (non-goals)

Проект **не** реализует:

* **настоящий KYC/KYB** — полноценную проверку личности клиентов и юридических лиц;
* **соответствие PCI DSS** — полный набор требований по безопасной обработке и хранению данных платёжных карт;
* **production secrets management** — промышленное управление секретами через Vault, KMS и аналогичные системы;
* **реальные payment rails** — интеграции с банковскими сетями, карточными системами и реальными платёжными провайдерами;
* **antifraud / fraud detection** — выявление подозрительных операций и автоматическую оценку риска мошенничества;
* **банковский compliance «как в проде»** — полноценное соответствие регуляторным требованиям, AML-процедурам, санкционным проверкам и внутренним банковским политикам.
