# ADR-008: Rate Limiting и Abuse Protection

## Статус

Принято.

## Контекст

Эндпоинты движения средств требуют более строгой защиты от злоупотреблений, чем обычные эндпоинты чтения.

Эндпоинты аутентификации также нуждаются в защите от атак запросами (brute-force).

Ключи идемпотентности хранятся бессрочно — для production нужна явная политика ограничения.

## Решение

LedgerPay определяет отдельные ограничения кол-ва запросов:

- `auth` — login/register;
- `api-global` — аутентифицированные API-запросы;
- `money-movement` — deposit/withdraw/transfer/retry;
- `backoffice-heavy` — тяжёлые backoffice-операции (reconciliation, сверка баланса).

Система также добавляет заголовки безопасности (security headers) для browser/API ответов и метаданных `idempotency_expires_at` с командой очистки.

## Последствия

Плюсы:

- снижение риска атак запросами (brute-force);
- ограничение случайных или вредоносных потоков транзакций;
- разделение лимитов по чувствительности эндпоинтов;
- явная политика хранения ключей идемпотентности.

Минусы:

- лимиты требуют настроек в production;
- для распределенных развертываний требуется серверная часть с общим кэшем (Redis);
- часть легитимного скачка трафика может быть отрезана.
