# ADR-010: Состояние, готовность и диагностика

## Статус

Принято.

## Контекст

Production-подобный backend должен отдавать операционные индикаторы состояния.

Простой сигнал «процесс жив» недостаточен: приложение может отвечать на HTTP, пока Redis, очередь или обработка outbox деградировали.

## Решение

LedgerPay предоставляет:

- публичный эндпоинт жизнеспособности (liveness);
- публичный эндпоинт готовности (readiness);
- Artisan-команду диагностики;
- страницу диагностики в бэк-офисе.

Проверки готовности охватывают:

- PostgreSQL;
- Redis;
- backlog очереди;
- backlog outbox;
- неуспешные транзакции.

## Последствия

Плюсы:

- проще отладка локально;
- понятнее история production готовности;
- прозрачность для эксплуатации;
- наглядная демонстрация в portfolio.

Минусы:

- пороги warning/failed требуют настройки под production;
- публичная готовность может потребовать защиты по окружению (allowlist, mesh).
