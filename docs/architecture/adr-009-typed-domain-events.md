# ADR-009: Типизированные доменные события

## Статус

Принято.

## Контекст

Запись событий через строки и разрозненные массивы усложняет рефакторинг и понимание контрактов.

Сообщения transactional outbox должны формироваться из явных доменных событий, а не из разрозненных массивов в прикладных сервисах.

## Решение

LedgerPay вводит классы типизированных доменных событий:

- `TransactionCreated`
- `TransactionCompleted`
- `TransactionFailed`
- `TransactionRetried`

Каждое событие описывает:

- название события (`event_name`);
- идентичность агрегата (тип, числовой id, публичный uuid);
- тело события (`payload`);
- дополнительные метаданные (`headers`).

Контракт — `IDomainEvent`. Запись в outbox выполняет `OutboxWriter::recordEvent()` через `DomainEventToOutboxMessageMapper`.

Строковая запись через произвольные массивы удалена; единственный путь в outbox — типизированный `IDomainEvent` и `OutboxWriter::recordEvent()`.

## Последствия

Плюсы:

- проще находить события и их контракты в коде;
- безопаснее рефакторинг;
- явная доменная терминология (DDD);
- единая централизованная форма тела события для транзакций.

Минусы:

- больше классов;
- позже потребуется версионирование событий;
- тело события `transaction.created` унифицировано с базовым `TransactionDomainEvent` (добавлены поля `status`, `processed_at`): внешние потребители, проверяющие точный набор ключей, должны обновиться; значение `event_name` не менялось.
