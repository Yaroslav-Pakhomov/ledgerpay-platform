# ADR-004: Ключи идемпотентности для движения средств

## Статус

Принято.

## Контекст

Клиенты могут повторять запросы из-за сетевых сбоев или тайм-аутов.

Без идемпотентности повтор приводит к дублированию вложения/вывода/перевода средств.

## Решение

API-эндпоинты транзакций требуют заголовок `Idempotency-Key`.

Ключ уникален среди транзакций.

Повтор с тем же ключом возвращает существующую транзакцию.

Ограничение по уникальности в БД — финальная защита от дубликатов.

## Последствия

Плюсы:

- безопасные повторы со стороны клиента
- предотвращение дубликатов
- предсказуемое поведение API

Минусы:

- область идемпотентности может потребовать уточнения
- нужна стратегия хранения/удержание ключей
